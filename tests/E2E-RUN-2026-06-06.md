# wp-to-astra — full end-to-end test run (2026-06-06)

Proves the **whole** rebuild workflow on disposable WordPress+Elementor instances
we control (Docker): detect Elementor → convert to native Astra/Gutenberg → make a
**real** UpdraftPlus backup → **restore it into a fresh WP via UpdraftPlus' own
restorer** → verify nothing is missing.

## Method (orchestrator-driven — placement NOT hardcoded)

Each instance was a job submitted to **maj-orchestrator** (`Dell:9002 /api/route/job`,
candidates `[dell,dgx]`, `required_gb=4`); the submitter ran it on whatever node the
orchestrator returned and reported back via `/api/learn`. No node was hardcoded.

**Placement decision:** orchestrator put **all 8 on Dell**. DGX had only ~26 GB live
free (vLLM holding ~94 GB) vs Dell ~129 GB, so best-fit kept DGX free. (An earlier
*forced* 4×DGX run failed for exactly this overload — which the orchestrator prevents.)

8 instances, full pipeline each, run in parallel on Dell. Per-instance wall 361–404 s.

## Result

```
instances:  8/8 PASS
checks:     120/120 PASS, 0 FAIL  (15 checks × 8 instances)
```

Each instance passed all 15 checks (8/8 each):
- theme_astra_active, seed_elementor_page
- dry_test_detected, elementor_removed, converted_content_native, gutenberg_blocks
- backup_set_complete, backup_has_manifest_log, db_has_converted_content,
  themes_zip_has_astra, plugins_zip_has_updraft
- restored_theme_files, restored_plugin_files, restored_converted_content,
  restored_no_elementor

The restore checks use UpdraftPlus' OWN restorer (`perform_restore`) into a fresh WP
+ separate DB import, then verify theme/plugin FILES are on disk, the converted page
is in the restored DB, and Elementor did not come back — i.e. the admin's failure
mode (DB restored but default theme / no CSS / dead shortcodes) does NOT happen with
the real, manifest-carrying backup.

## Bug found & fixed during validation

`wp-to-astra.sh` detected Elementor pages with a deeply-escaped inline `wpdb` SQL that
returned 0 when invoked through `docker exec` → the orchestrator **skipped convert**
and backed up the unconverted site. Replaced with `wp post list --post_type=page,post
--meta_key=_elementor_edit_mode --meta_value=builder --format=count`. Caught because
the test verifies conversion, not just "a backup was produced".
